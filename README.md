```text
[ Telegram App (Mobile / Desktop) ]

             │
             ▼ (HTTPS + WSS / HMAC-SHA256 InitData Validation)

   ├── Lead Agent & Turn-Taking Queue (Anti-Collision & Sequential Locking)
   ├── Dynamic Task DAG Planner (Task Tree Decomposition)
   ├── LLM Gateway (Gemini 2.5 Flash/Pro, Claude 3.5 Sonnet, GPT-4o, Ollama Local)
   ├── Shared Memory Engine (Correction Detector + Semantic Similarity Ranking)

   ├── Approval State Machine (TOCTOU Cryptographic Verification Gate)
   └── Crash Recovery & Audit Trail (Checkpoints, Outbox Pattern & Immutable Logs)
             │
             ▼ (Secure Token-Authenticated WebSocket Bridge / runner-ws)
[ Local Runner Daemon (ដំណើរការលើកុំព្យូទ័រផ្ទាល់ខ្លួន ឬ Docker VPS) ]

   ├── Sandboxed Tool Executor (Command Allowlist & Path Restriction)
   └── Diff Generator & Git Push/Merge Controller (រង់ចាំការអនុញ្ញាតពីមនុស្ស)
```

## ៣. ការរចនាយន្តការបច្ចេកទេសកម្រិតខ្ពស់ (Deep-Dive Engineering)

### ក. Turn-Taking & Anti-Collision Engine
- **Sequential Locking:** ប្រព័ន្ធចាក់សោបន្ទប់ឆាត (`room_lock:<room_id>`) មិនឱ្យ AI ឆ្លើយជាន់គ្នារញ៉េរញ៉ៃ។
- **Waiting Queue:** បញ្ចេញស្ថានភាពទៅកាន់ Mini Web ថា *"Advisor waits for QA, then answers"*។
- **Context Chaining:** លទ្ធផលពី Developer និង QA ត្រូវបានបញ្ជូនចូល Prompt របស់ Reviewer ស្វ័យប្រវត្តិ។
- **Loop Circuit Breaker:** បញ្ឈប់ការសន្ទនាស្វ័យប្រវត្តិកុំឱ្យអស់ថ្លៃ API ពេល `maxTurnsPerTrigger` ដល់កំណត់ ឬពេល QA ឆ្លើយ **QA PASS**។

### ខ. Git Worktree Isolation & TOCTOU Defense
- **គ្មានជាន់កូដគ្នា (Zero File Conflicts):** Agent នីមួយៗកែប្រែកូដតែក្នុង Folder Worktree ផ្ទាល់ខ្លួន (`worktrees/my-shop-dev-task42`)។
- **TOCTOU Protection:** រាល់ Approval Request ត្រូវបានចុះហត្ថលេខាដោយ `action_hash = SHA256(action_type + target_repo + branch + target_commit_sha + payload)`។ ប្រសិនបើ Commit លើ Branch ផ្លាស់ប្តូរមុនពេល Execute ប្រព័ន្ធនឹងបដិសេធស្វ័យប្រវត្តិ និងទាមទារការអនុម័តថ្មី។

### គ. Cross-Agent Shared Memory Pipeline
- **Correction Detector:** ចាប់ពាក្យគន្លឹះបង្រៀនទម្លាប់ក្នុងឆាត (ភាសាខ្មែរ និងអង់គ្លេស)។
- **Structured Scoping:** បែងចែករវាង `GLOBAL` (អនុវត្តលើគ្រប់ Agent គ្រប់ Project) និង `PROJECT` (អនុវត្តតែក្នុង Project ជាក់លាក់)។
- **Conflict Detection:** ពិនិត្យភាពផ្ទុយគ្នារវាងច្បាប់ចាស់ និងច្បាប់ថ្មី (ឧ. `npm` vs `pnpm`)។

### ឃ. Safety, Sandboxing & Cost Control
- **Prompt Injection Defense:** កំណត់កម្រិត Instruction Hierarchy (System > Human > Tool Output) និងដាក់កូដ/ឯកសារខាងក្រៅក្នុង Boundary Isolation `<<<UNTRUSTED_CONTENT>>>`។
- **Secret Redaction:** ស្កេន និងលុប API Keys, Private Keys, Passwords, JWT Tokens ដោយស្វ័យប្រវត្តិកុំឱ្យធ្លាយទៅ LLM APIs។
- **Sandboxed Tool Executor:** Local Runner អនុញ្ញាតតែពាក្យបញ្ជាដែលមានក្នុង Allowlist (`git`, `npm test`, `pytest`, `cargo`, etc.) និងហាមឃាត់ Path Traversal ដាច់ខាត។
- **AI Usage & Cost Tracker:** តាមដាន Token Usage និងគណនាថ្លៃដើមតាម Agent នីមួយៗ។

## ៥. របៀបតម្លើង និងដំណើរការ (Quickstart Guide)

### ជំហានទី ១: ដំឡើង Dependencies
អ្នកអាចចុចរត់ `scripts/setup.bat` (លើ Windows) ឬ `bash scripts/setup.sh` (លើ Linux/Mac) ឬដំណើរការដោយដៃ៖

```bash
# ដំឡើង Backend
cd backend && npm install

# ដំឡើង Local Runner
cd ../local-runner && npm install

# ដំឡើង Mini Web
cd ../web && npm install
```

### ជំហានទី ២: កំណត់បរិស្ថាន `.env`
ចម្លងឯកសារ `.env.example` ទៅ `.env`៖
```bash
cp .env.example .env
```
បញ្ចូល Telegram Bot Token និង API Keys (Gemini, Claude ឬ Ollama)។

### ជំហានទី ៣: ដំណើរការប្រព័ន្ធ
បើក ៣ Terminal ដំណាលគ្នា៖

1. **Terminal 1 - Orchestrator Backend:**
   ```bash
   cd backend && npm run dev
   ```
   *(Backend នឹងដំណើរការលើ `http://localhost:3000`)*

2. **Terminal 2 - Local Runner Daemon:**
   ```bash
   cd local-runner && npm run dev
   ```
   *(Runner នឹងភ្ជាប់ទៅកាន់ Backend តាម `ws://localhost:3000/runner-ws` ដោយស្វ័យប្រវត្តិ)*

3. **Terminal 3 - Telegram Mini Web:**
   ```bash
   cd web && npm run dev
   ```
   *(Mini Web នឹងដំណើរការលើ `http://localhost:5173`)*
